**Scope:** home page, analysis-in-progress state, new results layout (v3), old results layout (v1/v2). Desktop 1440, mobile 375, light and dark scheme.
**Live pages reviewed:**

- New layout: https://aitopicexplorer.app/results/cmw6z5qiv00cy0xp9ykugrp9s ("water use by Texas data centers")

Screenshots are in [`design-2026-11/`](design-2026-11/) and cited as `[S01]` etc. This is a review only; nothing was edited.

**Rubric:** there is no `design-language.md` in the repo, so the review is against the house canon (`development-guidelines:design`), `make-interfaces-feel-better`, `attribution-branding`, and the tokens actually declared in `app/globals.css` (cream `#F8F6F3` base, cyan/violet accents, three text greys, glass tiers).

---

## Verdict

The bones are good. The tabbed full answers, the "How it frames the topic" summary, the For/Against columns and the per-AI provider pills make the page genuinely useful, and the layout holds at 375px with no horizontal scroll. Two things hold it back. First, **a site-wide Tailwind v4 bug has flattened the whole colour hierarchy**: every `text-[--…]`/`border-[--…]` class (150 uses in 19 files) compiles to an empty rule, so secondary and tertiary text, the cyan accents and several borders all render near-black. Fixing that one pattern restores most of the intended design at once. Second, **the full-length prose isn't yet set for reading**: lines run ~100+ characters at 15px, citation markers don't match the numbered source list, and model chatter ("I'll search for current information on this topic.") leads every Claude answer. Fix those and the results page reads like a finished product.

## Detail

### 1. P0: Tailwind v4 is silently dropping the design tokens

**What's wrong.** The project is on `tailwindcss ^4`. In v4, a CSS variable in an arbitrary value must be written `text-(--text-tertiary)` or `text-[var(--text-tertiary)]`. The v3 shorthand `text-[--text-tertiary]` still compiles but produces an **empty rule**. Verified in the live stylesheet:

```
.text-\[--text-tertiary\] { }
.border-\[--accent-cyan\]\/40 { }
```

…while the one place that uses `border-[color:var(--accent-cyan)]` works. Measured on the live page: the "How it frames the topic" paragraph, its left border, the model id, and the answer prose all compute to `rgb(26,26,46)` (`--text-primary`), although they're coded as `--text-secondary`, `--accent-cyan/40` and `--text-tertiary`.

**Impact.** This is why the page feels heavy and flat: the three-level grey hierarchy the tokens define (`#1a1a2e` / `#64748b` / `#94a3b8`) is gone, hover states that should turn cyan don't, the frame callout border is black instead of soft cyan, link underlines are black, and the mobile header's `bg-[--bg-base]/80` background is missing (only the blur shows). It also makes every other visual judgement unreliable until it's fixed.

**Fix.** Replace the pattern everywhere: `-[--name]` → `-(--name)` (and `-[--name]/NN` → `-(--name)/NN`). Count by token: `--text-tertiary` 44, `--text-primary` 42, `--accent-cyan` 36, `--text-secondary` 23, others 6. A single codemod (`sed -E 's/-\[(--[a-z-]+)\]/-(\1)/g'` over `app/` and `components/`) does it; then recheck contrast, because `--text-tertiary #94a3b8` on cream is ~2.6:1 and will fail AA for body-size text once it actually renders (coordinate with 6.3 accessibility). Use `--text-tertiary` only for ≥18px or non-essential text, or darken it to ~`#6b7689`.

**Validate after.** Re-screenshot the results page: the frame callout should go grey with a cyan rule, model id light grey, prose `#64748b` (consider `--text-primary` at 90% for long prose instead; slate-500 on cream for paragraphs of reading is on the light side).

### 2. P0: Citation numbers point to the wrong sources

**What's wrong.** On the Grok tab `[S04]`, the prose's `[2]` links to houstonchronicle.com, but item 2 in "Sources it cited" is deceleration.news (houstonchronicle.com is item 4). The answer's numbering comes from the model; the list's numbering comes from `answerSources()` order after de-duplication (`lib/results/run-view.ts:141-158`). The markers also render as full-size underlined `[1][2]` text, the same weight as the sentence.

**Impact.** This is a trust product. A reader who checks a claim against its number lands on the wrong source.

**Fix.** Either (a) drop the visible numbers from the list and make each inline marker the link itself, or (b) map each inline `[n]` to the URL it links to and number the list by that. Render markers as small superscript pills (`text-[11px] align-super`, rounded, `tabular-nums`, 24px hit area via padding) rather than underlined brackets. For providers whose prose has no markers (Claude, ChatGPT in these runs), keep the list unnumbered.

### 3. P0: Attribution footer is the retired credit

**What's wrong.** Footer and results sidebar say "Built by The Canter Company" and link to a personal LinkedIn `[S01][S02]`. The `attribution-branding` standard replaced that credit with `Built by Above Public Affairs` → `https://abovepublicaffairs.com` and says to sweep the old one.

**Fix.** Swap the text and link in `components/Footer.tsx` and the sidebar copy in `components/ResultsShell.tsx`. aitopicexplorer.app isn't an Above domain, so no privacy-policy link is required by that rule; check with the privacy-policy skill given GA4 is loaded.

### 4. P1: Set the answers for long reading

**What's wrong.** `AnswerProse` is `text-[15px] leading-7` inside a `max-w-4xl` column, so prose runs 838px wide: about 89 "0"-widths, i.e. 100+ characters of mixed text per line `[S02]`. The canon's reading measure is 60–75ch. At 15px with long lines the eye loses its place on return; with 1,500-word answers that's the main reading cost of the new layout.

**Fix.** In `components/AnswerProse.tsx:50`: `text-base sm:text-[17px] leading-[1.7] max-w-[68ch]`. Keep the frame callout and the sources list at the same 68ch measure so their left and right edges line up with the prose. Leave the tab bar full width. Body colour: see §1. Optional: a slightly larger first paragraph (`text-[18px]`) as a lede.

Related: headings inside answers. Models write their own `#` / `##`; `AnswerProse` maps both to 18px `h3`. Fine, but add `scroll-mt` and consider a small "On this answer" list of those headings for answers over ~800 words.

### 5. P1: Strip model process chatter

**What's wrong.** Both Claude answers open with "I'll search for current information on this topic." / "…on this." `[S02][S06]`. It's the model narrating its tool call, not part of its answer. It's the first line of the Answers section, so it's what a reader sees first.

**Fix.** Drop leading tool-preamble sentences at save or render time (a short pattern list: `^I'll (search|look up|check)…`, `^Let me (search|look)…`), or keep only text after the last tool-use block in the Claude adapter. Stating "as it wrote it" on the page argues for doing it in the adapter (it's not part of the written answer) and noting it in the methodology modal.

### 6. P1: Clean the sources list

**What's wrong** `[S03]`, plus the live run:
- **Duplicates:** `epelectric.com/communitysolar` and `…?utm_source=openai` listed separately; `bigsuncommunitysolar.com` twice. `urlKey()` (`run-view.ts:121`) strips the hash and trailing slash but not tracking params or `www.`.
- **Junk titles:** "© 2026 Center for the New Energy Economy 1 State Brief: Texas BACKGROUND", a 9-line paragraph ("In Table 2, we estimate…"), "WATER USE REQUIREMENTS FOR DATA CENTERS IN TEXAS A", "OCTOBER 2025".
- **Bare domains:** Gemini and Grok sources show only `kvue.com`, `fox7austin.com` etc., visually indistinguishable from titled links and much lighter.

**Fix.** In `urlKey`, drop `utm_*`, `ref`, `fbclid`, `gclid` and a leading `www.`; also strip them from the displayed href. Title hygiene: reject titles over ~140 chars or with no lowercase letters, and fall back to `domain + path slug`. Visually, give every source the same two-line shape (title, then muted domain) so bare-domain rows don't look broken.

### 7. P1: Bug button covers content on mobile

**What's wrong.** `fixed bottom-6 right-6` pill, ~150×44, sits over the prose and the last theme pill at 375px `[S07][S05][S10]`.

**Fix.** On `<lg`, collapse it to a 44×44 icon button (bug icon, `aria-label="Report a bug"`), and add `pb-24` to the results `<main>` on mobile so the last line can scroll clear. Or move "Report a bug" into the mobile results header overflow and the footer, and drop the floating button on mobile.

### 8. P1: Copy still describes the old product

- Home hero `app/page.tsx:541`: "combine their responses into key themes, entities, and citations." Now the core is each AI's full answer side by side. Suggest: "Ask Claude, ChatGPT, Gemini and Grok the same question and read their full answers side by side, with the sources they cite and where they agree and disagree."
- `app/layout.tsx:23` meta/OG description still promises "X perspectives".
- Sidebar subtitle "AI Topic Analysis" under the topic is filler; replace with the run date and "4 of 4 AIs answered".

### 9. P1: Label the old layout

Old results `[S09][S10]` look like a different, sparser product (X Perspective, Citations grouped by domain, no answers) with no explanation. Add one muted line under the title in `ResultsContent.tsx`: "Saved with an earlier version of AI Topic Explorer. [Run this topic again] to see each AI's full answer." The link pre-fills the home input. Everything else on the old layout can stay; don't spend 6.6 time restyling it beyond fixing §1, which applies there too.

### 10. P2: Mobile results ordering and header

- Sticky header + nav takes ~205px (25% of an 812px screen) `[S05]`. Make the provider status row hide once scrolled (it's static information), keeping title + actions + section nav.
- Topic truncates to "water use by Texa…" and the full title appears nowhere on mobile. Show the full title as the page heading in the content (it's `lg`-only today) and keep the truncated one in the sticky bar.
- Key Themes occupies the full first screen; answers start at ~966px. On mobile, cap Key Themes to its top 6 with "Show all", or put Answers first; the full answers are the product now.
- The tab bar isn't sticky; in a 1,800px expanded answer, switching AI means scrolling back up. Make the tablist `sticky top-[header height]` within the Answers panel.

### 11. P2: In-progress state

`[S12][S13]`: the panel is clear and the timer uses `tabular-nums`, which is good. Issues:
- No expectation set. Runs take ~40–60s. Add "Usually about a minute" under the stage line.
- After all four dots go green, "Reading the answers…" holds 15–25s with nothing changing; it reads as stalled. Show a per-AI "reading" state (dot back to pulsing, or a small check appearing as each answer's extraction finishes, since `runPipeline` already extracts per answer).
- The disabled "Analyzing…" button at `opacity: .45` goes muddy over the gradient; use full opacity with a spinner and `cursor: progress`.
- Adding the panel re-centres the hero vertically, so the title jumps ~48px down (`app/page.tsx:518-525`, `md:items-center`). Reserve the panel's height or anchor the column to the top.
- Floating-keyword puzzles (fonts, Greek letters, weather words) are charming but unrelated to the product; fine to keep, but they're the busiest thing on the page while the user is waiting. Consider pausing the drift (`animation-play-state: paused`) during a run and honouring `prefers-reduced-motion` (coordinate with 6.3).

### 12. P2: Near-duplicate themes

Water run: "Growth projections", "Projected demand", "Projected growth". Solar run: "Local utility programs" / "Utility programs"; "No statewide framework" / "Statewide policy gap" / "Limited statewide policy". The merge (`run-view.ts:194`) is by normalised label, so synonyms survive as separate pills and look like padding. Fix in extraction (ask for canonical theme labels across answers, as 2.7 did for entities) rather than in the view; as a stop-gap cap to the top 8 with distinct head nouns.

### 13–17. Smaller items

- **13 Headings:** results pages have two `<h1>`s (mobile header and sidebar, both in the DOM) and the visible desktop topic is an `<h2>`. Make the in-content topic the only `<h1>`; sidebar/header titles become `<p>`. Also render the topic in sentence case for display (`water use…` → `Water use…`) while keeping the stored text.
- **14 Model ids:** `claude-sonnet-5-5` / `grok-4.3` in monospace read as debug output. Show a friendly name ("Claude Sonnet 5.5") in the sans face, with the raw id in a `title` tooltip.
- **15 Dark mode:** the site is light-only and stays fully light under `prefers-color-scheme: dark` `[S08]`, which is acceptable for launch. Add `color-scheme: light` on `:root` (and `<meta name="color-scheme" content="light">`) so form controls and scrollbars don't flip. A real dark theme is a bigger bet; don't start one until §1 lands.
- **16 Entities:** `md:grid-cols-2` places People (1 item) beside Organizations (14 items), leaving a big empty block, then Places under it `[S03]`. Use CSS columns (`columns-2 gap-8`, `break-inside-avoid` per group) so groups pack. Hide empty groups instead of "None identified" `[S09]`. Entity noise ("New York", "Colorado" in a Texas topic) is an extraction issue for later.
- **17 Provider colours:** the sidebar "Sources" list shows every provider as a green status dot while the tabs and pills use brand colours (orange/teal/blue/red). Use the brand dot in the sidebar and show status as text only when an AI failed.

## By dimension

- **House floor / anti-slop (`design`):** Glassmorphism tiers plus a six-layer mesh gradient on `body` is close to the banned "AI-default gradient glass" look, but it's restrained and on-brand for this product. Keep it; don't add more. The gradient brand button and gradient wordmark are the only gradients that should stay prominent. Attribution fails (§3).
- **Visual taste:** clean, legible, a little generic. The strongest move left is typographic: a proper reading measure and size (§4) will do more for perceived quality than any colour change.
- **Interface polish (`make-interfaces-feel-better`):** good: `active:scale-[0.96]` on tabs and buttons, `tabular-nums` on timers and counts, `text-pretty`/`text-balance`, 40px tab targets. Radii are consistent (16px cards, 8px tabs at 8px inset, full pills). Gaps: hover-only cyan states are dead because of §1. Citation markers lack hit area (§2).
- **Motion:** floating keywords run continuously; ensure `prefers-reduced-motion` stops them (6.3). Tab switch has no transition; a 120ms opacity fade on the panel would soften it. The "Read the full answer" expand is an instant jump; acceptable.
- **Responsive:** no horizontal overflow at 375 on any page. Mobile issues are ordering and chrome height (§7, §10).
- **Design system:** tokens exist in `globals.css` but the bridge to Tailwind is broken (§1); there's no `design-language.md`. After 6.6, write a one-page `design-language.md` capturing the tokens, the 68ch reading measure, provider colours and the pill/badge styles, so later work has something to check against.
- **Accessibility:** deferred to 6.3; the contrast issue in §1 (once tertiary text renders) and the duplicate `<h1>` (§13) overlap with it.
- **UX copy:** section subtitles are good and specific ("What the answers spend their time on. Larger means more AIs raised it, at more length."). Stale descriptions in §8. "Sources" appears twice with different meanings (sidebar provider list vs. citations section); rename the sidebar group "AIs".
- **Old layout:** same shell, same §1 problems; needs only the notice (§9) and the footer fix.
