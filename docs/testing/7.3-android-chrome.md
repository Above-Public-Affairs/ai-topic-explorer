**Date:** 2026-11-11 · **Site:** https://aitopicexplorer.app (live, main at b312fd3) · **Tester:** Claude (session for task 7.3)

> **This is Chromium emulation, not a real Android device.** Testing used the Claude desktop app's built-in browser pane: its `mobile` preset (375×812) sets an Android Chrome user agent (`Linux; Android 14; Pixel 8 … Chrome/156 Mobile`) and 5 touch points, and a custom 412×915 size did the same. One **major** issue: collapsing a long answer ("Show less") leaves the reader thousands of pixels further down the page. The rest are minor and polish items, mostly small tap targets.

## Issues

### Major

<a id="m1"></a>**M1. "Show less" (and "Show fewer") leaves the reader far below the content they collapsed.**
- Steps: results page → Answers → ChatGPT tab → "Read the full answer" → scroll to the bottom of the answer → tap "Show less".
- Result: the answer collapses from ~8,000px to ~1,250px but the scroll position stays put, so the viewport lands in the Sources section or the footer. At 375 the answer was 6,400px above the viewport afterwards; at 412 (Gemini tab) 2,173px. The same happens, on a smaller scale, with "Show fewer" in Arguments (button ends up 432px above the viewport).
- Expected: after collapsing, the top of the answer (or the toggle) stays in view, e.g. scroll it back into view on collapse.
- Screenshots: `docs/testing/7.3-screenshots/375-11-after-show-less.jpg`, `docs/testing/7.3-screenshots/412-06-after-show-less.jpg`

### Minor

<a id="m2"></a>**M2. Several tap targets are under 40px (Android guidance is 48dp).**
- Measured at 375 and 412: section nav links (Key Themes … Sources) 32px tall; header Share 34px and New Topic 32px; smaller theme chips 26px (larger ones 34–42px); Arguments "source" links 39×32; single-line source titles in Sources 19px tall; example chips on home 38px. Footer links, dialog close buttons, answer tabs and "Read the full answer" are all 40px+.
- Screenshots: `docs/testing/7.3-screenshots/375-07-results-top.jpg`, `docs/testing/7.3-screenshots/375-12-arguments.jpg`

<a id="m3"></a>**M3. Shared results links have no preview image.**
- Steps: fetch any `/results/…` page and look at its meta tags.
- Result: home has `og:image` (`/opengraph-image?…`), results pages have no `og:image` or `twitter:image`, although `twitter:card` is `summary_large_image`. `twitter:title` on results is "AI Topic Explorer" while `og:title` is the topic. A results link pasted into Messages, WhatsApp or Slack on Android will show a text-only card.
- Likely cause: the results page's `generateMetadata` sets `openGraph` and so replaces the inherited image (Next.js does not merge it).
- Screenshot: n/a (meta tags; checked via fetch).

<a id="m4"></a>**M4. Landscape is cramped.**
- Steps: 812×375, open a results page, then home.
- Results: the sticky results header is 129px of a 375px viewport (34%; on a real phone Chrome's address bar takes more), leaving ~245px for reading. On home the two-column layout puts the topic box at y=351, so it is below the fold on load.
- Note: at widths ≥768 the pane drops the Android UA and touch, so this pass is layout-only.
- Screenshots: `docs/testing/7.3-screenshots/landscape-01-results.jpg`, `docs/testing/7.3-screenshots/landscape-02-home.jpg`

### Polish

<a id="p1"></a>**P1. Changelog only reachable from the home page.** The results-page footer has "Built by…" and "Privacy policy" but no Changelog (home footer has all three). May be intentional; flagging for a decision.

<a id="p3"></a>**P3. Bug form: character counter touches the helper text at 412.** "…included automatically." ends at x=329 and "0/2000" starts at x=329 (0px gap). At 375 the helper text wraps and the gap is fine.

**P4. Share label swap reflows the header title.** When "Share" becomes "Copied" the button width changes and the clamped topic re-wraps ("Effects of community / composting…" → "Effects of / community…"). A fixed-width button would avoid the jump.
Screenshot: `docs/testing/7.3-screenshots/375-13-share-copied.png`

**P5. Possible glyph-clipping artifact in an expanded answer (unconfirmed).** In the ChatGPT answer, the "g" of "guaranteed" at the start of a line rendered with its bowl clipped, consistently across scrolls and re-renders. The DOM is plain text with nothing overlapping, so this is probably a Chromium rasterisation artifact of the glass/backdrop layers; check on a real device before acting.
Screenshot: `docs/testing/7.3-screenshots/375-10-answer-expanded-glyph.jpg` (line 4 of the text)

**P6. Small layout nits.** At 412 the home intro paragraph (`text-wrap: pretty`) leaves a short second line ("the same question and read their"); in landscape the "Pause animation" pill sits on top of a floating keyword.
Screenshots: `docs/testing/7.3-screenshots/412-01-home.jpg`, `docs/testing/7.3-screenshots/landscape-02-home.jpg`

## Not covered

Emulation in a desktop Chromium pane can't show:

- **The real Android keyboard**: how Gboard covers the topic box and bug form, whether the dialogs stay usable with the keyboard open, the Enter-key label, autocorrect and autocapitalise behaviour.
- **The system share sheet**: `navigator.share` doesn't exist in the pane, so only the copy-link fallback was tested. On real Android Chrome, Share will open the native sheet; that path is untested.
- **The back gesture / back button**: whether back closes an open dialog (native `<dialog>` should get a `cancel` event) or leaves the page, and back after following an anchor link.
- **Performance**: real CPU/GPU, scroll smoothness with the glass/blur effects and floating keyword animation, memory on long results pages.
- **Real network**: mobile latency and dropped connections during the ~70 s streaming analysis, and whether the stream survives the screen locking or the tab going to the background.
- **Chrome's own UI**: address bar showing/hiding and its effect on `100vh`/sticky header, pull-to-refresh, overscroll glow, Chrome's "Auto dark mode for web contents" flag (the site declares `color-scheme: light`, which may or may not stop it).
- **New tabs**: the pane opens `target="_blank"` links in the same tab, so opening the privacy policy and sources in a new Chrome tab wasn't seen.
- **Fonts and rendering**: Android's system font fallback and real-device text rendering (see P5).

## Method notes

- Taps via the pane's click tool; measurements via `getBoundingClientRect` in page JavaScript. Screenshots in `docs/testing/7.3-screenshots/` (`375-*`, `412-*`, `landscape-*`).
- The Share fallback copied the results URL to the test machine's clipboard (the pane denies `clipboard.writeText`, and the site's fallback copy succeeded).
- Viewport was reset to desktop at the end.
