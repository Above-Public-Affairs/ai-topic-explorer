## Issues

### 1. Key Themes shows near-duplicate themes. Major

**Browser:** both (it's in the data). **Screenshot:** `screenshots/7.1/chrome-results-1440.png`

**Steps:** run "Asteroid mining feasibility" and look at Key Themes.

**Seen:** "Technical hurdles", "Technical progress and hurdles" and "Technical challenges" sit side by side, as do "Economic viability", "Commercial viability", "Commercial economics" and "Economic barriers". The Safari run ("Water scarcity solutions") had the same pattern: "Water supply" / "Supply expansion" and "Efficiency and conservation" / "Water efficiency" / "Agricultural efficiency".

**Expected:** these merge into one theme each (the 4.8 theme merge), so the cloud shows distinct ideas and the size reflects real cross-AI agreement. This is the headline visual on every results page, which is why it's rated major.

### 2. Changelog isn't reachable from results pages. Minor

**Browser:** both. **Screenshots:** `chrome-results-1440.png` (sidebar footer), `chrome-results-600-bottom.png` (narrow footer)

**Steps:** open any results page and look for Changelog in the footer.

**Seen:** the results sidebar footer and the narrow-width page footer show only "Built by Above Public Affairs · Privacy policy". Home shows "… · Changelog".

**Expected:** the same footer links on every page, if the in-site changelog is meant to be reachable everywhere.

### 3. Shared results links have no preview image, and `twitter:title` is generic. Minor

**Browser:** both (server-rendered meta).

**Steps:** `curl` a results URL and read its `<meta>` tags.

**Seen:** `og:title` is topic-specific, but there's no `og:image` or `og:url`. `twitter:card` is `summary_large_image` with no image, and `twitter:title` is just "AI Topic Explorer".

**Expected:** a share image, or a `summary` card, and a topic-specific `twitter:title`. Shared links will unfurl without an image on Slack, X and iMessage.

### 4. Duplicate sources and tracking parameters. Minor

**Browser:** both (data). **Screenshot:** `chrome-sources-nasa.png`

**Steps:** results for "Asteroid mining feasibility", Sources section.

**Seen:**

- A "NASA.GOV" group holds two ChatGPT sources, but a separate ungrouped "NASA" entry (also nasa.gov) appears a few rows below.
- "Overview: In-Situ Resource Utilization - NASA" (`/overview-in-situ-resource-utilization/`) and "NASA" (`/overview/in-situ-resource-utilization/`) look like the same page.
- The Arguments "source" link and the NASA entity link point to `…in-situ-resource-utilization/?utm_source=openai`. The changelog says tracking codes are removed.
- Three different sites are titled just "Asteroid mining market" (titles built from the URL slug), so they're hard to tell apart.

### 5. Theme context excerpts include bare headings. Polish

**Browser:** both. **Screenshot:** `chrome-theme-open.png`

**Steps:** click the "Technical hurdles" theme.

**Seen:** "Technical feasibility" (Claude) and "Technical Aspects" (Grok) appear as excerpts. They're answer headings, not sentences.

**Expected:** sentence-level excerpts only.

### 6. Bug report textarea has no `id` or `name`. Polish

**Browser:** Chrome (DevTools Issues panel: "A form field element should have an id or name attribute").

**Steps:** open Report a Bug and check DevTools Issues.

**Seen:** the `<textarea>` in `components/BugReportButton.tsx:112` has neither attribute. It's labelled with `aria-label`, so it isn't an accessibility failure, but autofill and DevTools flag it.

### 7. Results sidebar footer wraps awkwardly. Polish

**Browser:** both (desktop sidebar). **Screenshot:** `chrome-results-1440.png`

**Seen:** under "Built by", "Above Public Affairs" and "Privacy policy" each wrap onto two lines side by side with a floating "·" between them.

**Expected:** each link on its own line, or the shorter "Above" (per the org rule on the short name).

### 8. Narrow results page: empty band and double rule above the footer. Polish

**Browser:** Chrome at 600px. **Screenshot:** `chrome-results-600-bottom.png`

**Seen:** about 140px of empty space after the Sources card, then two horizontal rules, then the footer.

### 9. Floating words collide with controls. Polish

**Browser:** Chrome at 1280 and 900. **Screenshots:** `chrome-focus-1280.png`, `chrome-home-900.png`

**Seen:** the "Pause animation" pill sits on top of a floating word ("Block"). At 900px, a floating word ("Promote") butts against the Explore button. The words are decorative, but the overlaps look unintentional.

### 10. Safari: mouse-opened dialogs don't return focus to their trigger. Polish

**Browser:** Safari STP.

**Steps:** click "How does this work?" with the mouse, then press Esc.

**Seen:** focus lands on a page container, not the button. With the keyboard (focus the button, Enter, Esc), focus returns correctly. This happens because Safari doesn't focus buttons on click, so there's nothing stored to return to. Fallback: return focus to the trigger element explicitly rather than to `document.activeElement` at open time.

### 11. "Tap any theme" copy on desktop. Polish

**Browser:** both. **Screenshot:** `chrome-how-it-works.png`

**Seen:** How It Works step 3 says "Tap any theme…", while the results page says "Click any theme to see it in context". Use one input-neutral word, such as "Select".

### 12. "AIs" label reads "AIS". Polish

**Browser:** both. **Screenshot:** `chrome-results-1440.png`

**Seen:** the sidebar heading uses `text-transform: uppercase`, so "AIs" shows as "AIS" and appears that way in the Chrome accessibility tree. Screen readers may read it as a word.

### 13. Client-adjacent placeholder. Note

**Browser:** Safari STP (the placeholder rotates).

**Seen:** the topic box placeholder cycled to `e.g. "oil and gas in New Mexico"`. This isn't a bug, but it's close to a client's issue area on a public tool, so it's worth a deliberate yes or no.

## Not covered

- **Firefox, all steps.** Not installed, and no tool here can drive it.
- **Release Safari.** Only Safari Technology Preview was tested. STP runs a newer WebKit than release Safari.
- **Safari keyboard tab order and visible focus ring.** By default Safari's Tab key only moves between form fields; reaching buttons and links needs Option+Tab or the "Press Tab to highlight each item" setting. The harness can't send Option+Tab, and programmatic `.focus()` doesn't trigger `:focus-visible` there. Esc-to-close and focus return were verified.
- **Safari at 1280px and narrower.** `set_viewport_size` wouldn't go below 1440 wide ("invalid width").
- **Safari animations and smooth scroll.** The automated window is `document.hidden`, so CSS animations and `requestAnimationFrame` are frozen. That covers entrance fades, the floating words, "Pause animation" and keep-in-view on collapse. Safari viewport screenshots also came back blank; full-page captures worked, but they drop the fixed sidebar and background (`safari-arguments-capture.png`).
- **Submitting a bug report.** Deliberately not done.
- **Privacy policy page content.** Checked only that the link target returns HTTP 200, not the page itself.
- **Error states** (provider failure, rate limit, over-budget). These can't be triggered without forcing failures or spending more analyses.
